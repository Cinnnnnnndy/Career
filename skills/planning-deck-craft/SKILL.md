# 规划汇报材料写作

适用：给领导或评审讲的年度/版本规划（体验规划、产品规划、设计规划）。目标与指标的细节写法交给 ux-goal-setting，交稿前的领导视角审视交给 gao-review（见第八节）。

总原则：Why 先于 What 先于 How，每一段都要能落到「效」上。正文 20 页左右，其余放附录。骨架不改，只换业务内容。

## 一、骨架（经典，保留）

0. 概览
1. 背景
2. 用户
3. 竞品
4. 策略
5. 已落地进展
6. 下阶段规划
7. 目标与测量
8. 收尾（遗留问题、全景图）

新汇报先按这八段搭目录，再往里填内容。

## 二、每一部分的写法

### 0. 概览（1 页）
- 目录式：每段一行，写这一段的结论，不写段名本身（不要「背景介绍」，要「设备和开发者持续增长，体验要从可用走向好用」）。
- 放进主张、三条策略、TOP3、业务目标和边界（不做什么）。
- 评审只看这一页也能知道要做什么、为什么、做到什么程度。

### 1. 背景（2–3 页）
按三股力依次讲，最后收成一句「所以要……」：
- **规模/生态**：设备数、开发者数、应用数等官方数字，一个口径。结论句型：「规模持续增长，体验需要从可用走向好用」。
- **技术冲击**：时间线 + 一两个权威数据（如 AI 能独立完成的任务时长、工程师用 AI 交付代码的比例）。时间线节点只增不删；不放信任度一类会分散注意力的统计。
- **角色转变**：前后对照：原来工具做什么、人做什么 → 现在工具做什么、人做什么（例如人从写代码转到描述意图、确认计划、验收结果）。
- 常见问题：数据太多太杂、用第三方数字、口径不一、背景铺垫太长。

### 2. 用户（3–4 页）
- **用户分类页**：按根因分，不按行业或规模分（例如按工程体系成熟度分三类）。表格对照：特征 / 已有能力 / 需要我们提供什么。最后一句点明：流程基本一致，差异在侧重。
- **洞察页**：标题就是结论，下面一行副标题。洞察控制在两条大的，每条写成「从 A 转向 B」，配访谈份数（如 9/12）和一句原声。用框架组织发现，给观点而不只是罗列事实。
- **旅程页**：外圈是阶段（准备 → 开发 → 验证 → 发布），内圈是一次 AI 任务（执行前 / 中 / 后）；问题用红色胶囊标在对应阶段旁并带份数；最后列出旅程的三个关键变化。
- 旅程是高度概括的，要在备注里准备「不同角色有什么不同」的答案。
- 样本缺口（某类用户没访谈到）写进收尾的遗留项；没有样本的用户类型，不要替他写卡点。

### 3. 竞品（总览 1 页 + 每个趋势 1 页）
- **总览页**：三到四个趋势，每个都写成「从 X 到 Y」。
- **趋势页**：标题是这个趋势的完整一句（两行内）；两三个要点，每点配真实产品截图，写明产品、功能和时间。
- 按趋势组织，不按产品逐个罗列；准比全重要；趋势页之间不重复，同一个例子只出现一次。
- 覆盖友商平台（iOS、Android 等）的例子，说明这些变化不只发生在自家用户身上。
- 「对我们意味着什么」不写在趋势页，留到策略页统一收口。对领导讲时竞品段宁短勿长。

### 4. 策略（1–2 页）
- 先一句根趋势（如「从指挥走向托付」），再推出三条策略。
- 每条策略写：用户口吻的短名（四五个字，如「托付得放心」「验得了」「接得进」）+ 一句定义 + 它回答的问题 + 推动哪个业务目标 + 一个专属颜色（全篇一致）。
- 三条按「回答什么问题」切开（过程 / 结果 / 边界），保证互斥。
- 可以标出相对竞品的位置：跟上 / 做深 / 补齐。
- 写明不做什么（例如不拼模型、不自建通用 Agent）。
- TOP3 的说法从这里定下，后面逐字沿用、同一标记。

### 5. 已落地进展（2–4 页）
- 按策略归类，每项写：做了什么 + 效果（结果量：数据或用户反馈，不写过程量）+ 截图。
- 每个场景讲完收一句设计特征。
- 状态写准：已落地 / 落地中 / 探索中，不能把进行中写成已落地。
- 同一设计的动画分步收成一页代表页，这一段不超过全篇三分之一。

### 6. 下阶段规划（总览 1 页 + 每个专题 1 页）
- **总览页**：策略 × 阶段（或时间线）的矩阵，专题按策略颜色标注；优先级没定就把专题放在一张卡片里，不排序，备注里写「顺序评审后定」。
- **专题页**：专题标题 + 一个策略标签（整页同一策略时只打在专题标题上）；下列设计点，每点写名称 + 一句用户价值 + 图。
- 有点就要有图，不要整页纯文字罗列。
- 平台特色能力用统一的标签样式标出来，不做一次性的临时标签。
- 节奏从上市时间往回倒排关键节点，标出外部依赖、风险和预案。

### 7. 目标与测量（1–2 页）
- 两层目标：**达成**（体验指标，如 NSS）和**支撑**（业务目标，如接入家数）。
- 每条策略写一句目标，往下对应专题 → 设计点 → 体验指标，做成一张表。
- 指标必须是用户能感知的体验指标（成功率、耗时、单项满意度），不是性能或功能测试指标；每个指标能回指用户页的一个卡点。
- 没有基线就写「基线后定」并写建基线的时间，不编数字；标题下加一行「待与产品线对齐互锁」。

### 8. 收尾
- 遗留问题与下一步：每条一行，写问题 → 下阶段动作 → 时间（样本缺口、缺数据、未实测的对照、待对齐事项、上次汇报的遗留）。
- 最后一页写清需要领导决策或支持的事项。
- Thanks 之后可以放一张业务全景图（领域 / 产业 / 场景 / 产品 / 底座的分层网格），作为背景参考页。

## 三、贯穿全篇的方法

- **两头往中间推**：外头从竞品和趋势拿「先进性」，里头把已有规划点往上归类保「落地」，两头在策略层会合。
- **反推验证**：写完后倒过来查：目标、用户痛点、已落地、规划、遗留项能不能都挂到某条策略上？挂不上的就是漏洞或多余。
- **病-药-效**：每条策略都能写成 痛点 → 设计 → 指标。一页只讲一个痛点，痛点后紧跟对应策略。
- **层级固定**：策略 → 专题 → 设计点，每个专题只属于一条策略，映射关系做一张对照表，全篇按表来。
- **用词统一**：术语定下来后全篇一致，改名就全篇一起改；说人话，同时保持专业。
- **体验边界**：交互、搜索、提示这类问题算体验；内容准确、模型能力、生态收益不算体验，放进背景或「体验之外」。

## 四、数据

- 只用官方发布、权威媒体、正规机构的数据；第三方数字要标注来源，或者干脆不用。
- 同一个指标全篇只用一种口径和一个日期；讲稿和页面用同一个数。
- 不知道出处的数字直接删掉，不编，也不在页面上留「待补」；待补清单单独放一个文件。

## 五、预判追问

提前在页面或演讲者备注里准备好答案，格式「问 / 答 / 依据」：
- **覆盖面**：只讲了一个平台或一类用户，其他平台（iOS、Android）呢？
- **角色差异**：概括的旅程对大客户、中型企业、个人开发者分别意味着什么？
- **新范式的代价**：提出「看结果不看代码」这类转变时，代码冗余、规则检查、二次编辑怎么保证？
- **准出标准**：用户怎么定义 AI 做完了、做对了，怎么减少检查成本？
- **无人值守时的成果**：AI 在非工作时段做的事，怎么检验？
- **看不见的产出**：后端、脚本、配置这类不可视的结果，怎么管控、理解和验证？
- **数据出处**：每个数字从哪来、是什么口径？
- **效果**：已经做的部分效果怎么样？

## 六、页面与视觉

- 标题即结论（观点句，不是名词），最多两行，下面一行副标题，内容从固定位置开始。
- 大图大文字，能放图就放图，能配视频就配视频。
- 页面上只讲内容，不写讲 deck 自身的话（如「以下来自前文洞察」），出处和免责声明放演讲者备注。
- 大段文字里加粗关键词句；每页都有演讲者备注，复制页面时备注常带旧稿，要重写。
- 颜色按含义用：每条策略一个色系，前后呼应；红色只表示问题；强调用加粗，不用彩色字。
- 卡片用平铺底色，不用渐变，不用左侧彩色竖条，文本框不加描边，不留空框；留白克制，突出重点。
- 统一视觉时只改样式（颜色、字体、字号、圆角），不删元素：背景、连线、标签底都有含义。
- 同一个概念的图全篇用同一种画法。
- 字号不小于 16pt；标题、副标题、左栏对齐到统一网格；图片在版式允许的范围内尽量放大。

## 七、改稿协作

- 只改对方要求改的地方。标题、时间线节点、原有元素，没问过不动。
- 对方只说「名字难懂」时只换名字，不顺手换形式；形式类决定等对方定。
- 对方习惯一次说完所有意见再改：先记录清单，等对方说完再一起动手。
- 大改先出样张，确认后再合进正式文件；新页放在原页后面，原页设为跳过，不删。
- 按页标题找页，不按页码（对方可能同时在调整页序）。
- 动手前先备份；改完和备份逐页对比，确认没有误删或误改；最后重新导出 PDF。
- 对方同时在编辑文件时，先确认没有未保存的改动，不要覆盖对方的修改。

## 八、交稿前检查（用高老师视角 gao-review）

交稿前用 gao-review 按「汇报 PPT + UX 目标 / 项目规划」两类材料审一遍，结果交作者定，不自动返工。

**侧重**：战略与商业 ★★★、汇报逻辑与材料质量 ★★★、项目管理与协同 ★★★、设计品质与竞争力 ★★；涉及 AI 时「AI 时代的设计角色」★★★；引用用研时「用户研究报告」★★。

**步骤**（同 gao-review）：
1. 一句话复述：这份材料想让领导得出什么结论、做什么决定。复述不出来就是第一号问题。
2. 抽出全部页标题连起来读：能不能独立讲清 Why → What → How？标题是不是观点句？
3. 按下面的规划类清单逐条查，每个问题指到具体页。
4. 模拟会上最可能被问的 5 个问题，标出材料里有没有答案（第五节的追问一并核对）。
5. 每个问题给能直接动手的改法：改写后的标题、重排后的目录、补一页的提纲。
6. 按 P0（会上大概率被打断或否掉）/ P1（会被追问、影响印象）/ P2（细节打磨）排序。

**规划类清单**（按 gao-review 七个维度）：
- **战略与商业**：封面后有一页结论；先讲商业目标和用户价值；每条策略写明推动哪个业务目标（目标互锁）；TOP3 不超过三件，全篇同一说法、同一标记，没有游离在策略外的「重点」页。
- **汇报逻辑与材料质量**：Why 不晚不散，背景不冗长；每页一个观点、标题是观点句；每个场景走完病-药-效并收一句设计特征；用真实用户场景和旅程串起来，不按功能罗列；大图大文字；讲结果量不讲过程量。
- **设计品质与竞争力**：提炼出两三个设计特征词；和标杆竞品对比，说清持平还是超越；已落地部分有上线截图或还原效果。
- **AI 时代的设计角色**：AI 方案有信任设计（来源可见、可干预、可撤回）；交付物不只是加一个对话框。
- **项目管理与协同**：节奏从上市时间倒排；有风险和预案；有争议的结论标明各方意见、做过预沟通；有遗留问题页，上次汇报提的问题有回应。
- **用户研究**：洞察是观点不是事实罗列；用框架组织发现；竞品准而非全。
- **细节**：截图里的个人项目名、对话内容已模糊；颜色不和含义冲突；数字有出处、星号有脚注、讲稿和页面同口径；隐藏页的旧说法已清理；PDF 与最新 key 同步，文件名带当天日期。

**输出**：用 gao-review 的格式（一句话复述、总体判断、P0/P1/P2、会上最可能被问的 5 个问题、标题改写表、缺失信息）。
