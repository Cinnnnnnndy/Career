## UX 设计目标制定（ux-goal-setting）

来源：UCD 中心 2026 年 UX 设计项目目标制定研讨会（To B / To C / To D 三场，2026-05-27～29）的原始目标、SMART 刷新版、会上修改版和评委点评。范例已脱敏：不含人名、工号，客户局点、产品名和品牌做了泛化。

内容结构：

1. 方法论：一条目标 = 场景与问题 → 设计策略与设计点 → 体验结果 → 落地 → 支撑业务
2. 评委反复强调的 14 条原则（设计策略而非功能、基线与量化、NSS 统一口径、时间点与局点、支撑/达成用词、交付沿途与创新分开、句式精简等）
3. 按项目场景调整：用户类型（To B / To C / To D）× 项目性质（首版本、改版、迭代、创新、AI、平台沉淀、内容型站点）
4. 表述方式：模板、常用动词、设计点“三连”语料、功能化 → 设计化对照、避免的写法
5. 写作步骤、自检清单、6 个“原始 → 评委点评 → 改写”范例、输出格式

使用：在 Claude 里保存为 skill 后，直接贴一段 UX 目标说“帮我诊断/改写”，或说“帮我写 xx 项目的 UX 目标”。

## 高老师视角材料审视（gao-review）

来源：Cindy 整理的三层领导高老师的核心关注点（战略与商业、汇报逻辑与材料质量、设计品质与竞争力、AI 时代的设计角色、项目管理与协同、设计师能力、用户研究报告七个方面）。

内容结构：

1. 七个审视维度：每个维度列“看什么 → 问题信号 → 高老师式追问”
2. 按材料类型（汇报 PPT、设计方案、用研报告、UX 目标/项目规划）调整各维度侧重
3. 审视步骤：识别材料 → 一句话复述 → 骨架检查 → 逐维度审 → 模拟追问 → 修改建议 → P0/P1/P2 排序
4. 输出格式（含“会上最可能被问的 5 个问题”和标题改写表）、常用改写对照
5. “高老师常说的话”：按 Why 与商业、Top3 与聚焦、叙事结构、设计品质与竞争力、AI 时代、落地与项目、用研报告、对设计师的要求八组，收了可直接对照和引用的口径（来自 2025-07～2026-05 各类汇报与辅导记录的转述，已去掉人名、项目、客户与局点信息）
6. 与 ux-goal-setting 互相引用：目标写法细查交给 ux-goal-setting，领导视角审视交给本 skill

使用：在 Claude 里保存为 skill 后，贴上材料（或上传 PPT/PDF）说“用高老师视角帮我审一下”，或“快速过一遍”只看必改项和会上可能被问的问题。

## 规划汇报材料写作（planning-deck-craft）

来源：DevEco 26X/27X 体验规划汇报（2026-10）从起稿、多轮评审到定稿的经验，已去掉业务内容，只留框架和技巧。

内容结构：

1. 经典八段骨架：概览 → 背景 → 用户 → 竞品 → 策略 → 已落地进展 → 下阶段规划 → 目标与测量 → 收尾
2. 每一部分的写法：页数、页面结构、标题句型、常见问题
3. 贯穿全篇的方法：两头往中间推、反推验证、病-药-效、策略 → 专题 → 设计点、用词统一、体验边界
4. 数据口径、预判追问、页面与视觉、改稿协作
5. 交稿前检查：用 gao-review 按「汇报 PPT + 项目规划」审一遍，附规划类清单

使用：在 Claude 里保存为 skill 后，说“帮我搭一份 xx 规划汇报的骨架”或“按规划汇报的写法帮我改这一部分”；交稿前说“按交稿前检查过一遍”。

## Keynote 改稿（keynote-deck-polish）

来源：一份年度体验规划汇报材料的完整改稿过程（多轮反馈、全篇对齐、补新页、导出改名），以及当天的领导评审意见。只保留框架和技巧，不含业务内容。

内容结构：

1. 安全护栏：改前备份、检查未保存编辑、不删只移（画布外 / 跳过）、按标题找页、每项保存并汇报、最后改名
2. 视觉规范 token：边距、眉题 / 标题 / 副标题位置、卡片圆角与间距、胶囊、最小 16pt；颜色按含义用；不要装饰竖条、文本框描边、空框、元说明
3. 内容表达原则：未定的事不暗示已定、整组一致的标签提到上一级、临时标签统一样式、不编数据、备注与页面一致
4. 每一部分的写法（references/section-writing.md）：叙事线、标题体系、各部分版式与句子写法
5. 全篇对齐巡检：导出前图 → 几何普查 → 自动找差 1–4px 的问题 → 分类修 → 字号放大后查截断 → 导出后图与总览对比
6. Keynote AppleScript 的坑（references/applescript-gotchas.md）和 7 个可复用脚本
7. 原生形状重建页面：python-pptx 按 pt 建页 → Keynote 打开 → 菜单全选 / 拷贝 / 粘贴进目标页
8. 交稿前检查（references/final-review-checklist.md）：五条硬标准、篇幅结构、追问、细节
9. 汇报节奏

与 planning-deck-craft 的分工：写什么、怎么搭骨架看 planning-deck-craft；在 Keynote 文件里怎么安全地改、对齐和补页，看本 skill。

使用：在 Claude Code 里放到 `~/.claude/skills/keynote-deck-polish/`，然后说“把这份材料整体对齐一下”“按反馈改第 N 页”“把这张图做成原生形状放到某页后面”。

## 竞品分析（competitive-analysis）

来源：AnalysisSKILLS 仓库（SchihHsin/AnalysisSKILLS）。

内容结构：

1. 四阶段流水线：Stage 1 规划 → Stage 2 搜集 → Stage 3 分析（Markdown 报告）→ Stage 4 可视化（可选）
2. 分析视角在 Stage 1 显性确认（UX / PM / UI / Tech / Strategy），之后的维度、骨架类型、对比表行维度都跟随视角预设
3. 意图路由：new / continue（恢复中断或增量 diff 更新）/ visualize / query / fast（快速模式）
4. Human-in-the-Loop 检查点、进度汇报格式、每次回答末尾的当前阶段信息
5. 搜集规则：图文对照、多模态视觉核查截图、截图视觉解析写入 visual-analysis.md、事实标注
6. 洞察闭环（证据 / 分析 / 建议），写完整报告前先确认 3 条洞察方向
7. 可视化两种形态：楼层滚动 HTML 深度报告，或委派 references/guizang-ppt-skill 生成横向翻页演讲 PPT（电子杂志风 / 瑞士风）
8. references/：搜集方法论、分析框架、可视化框架、事实核查协议、报告与跟踪表模板、示例对话；GUIDE.md 为用户使用说明

使用：在 Claude Code 里放到 `~/.claude/skills/competitive-analysis/`，然后说“帮我做一份 xx 的竞品分析”，或 `/competitive-analysis fast A vs B`；分析完成后说“做成 PPT”或“生成 HTML 报告”。

## 竞品分析 bufan 版（competitive-analysis-bufan）

来源：同一仓库的早期版本。与主版本的区别：专家视角按需切换而非 Stage 1 显性确认；Stage 1 分四步（目标 → 范围 → 维度 → 规划）；Stage 2 有更细的图文下钻人机互动规则（预期管理、逐链接汇报、失败可感知、素材质量确认）和 YouTube / 浏览器截图流程；Stage 4 只做 HTML 楼层报告。目录内附 figma-d2c 的示例素材（materials/）、跟踪表（tracking/）和报告（reports/）。

使用：放到 `~/.claude/skills/competitive-analysis-bufan/`。两个版本同时安装时，说“用 bufan 版做竞品分析”来指定。
