# Keynote 汇报材料精修

这份 skill 是从一次完整的汇报材料迭代（多轮反馈、全篇对齐、补新页、导出改名）中提炼的方法。重点是**框架和技巧**，不含具体业务内容。业务语义（策略名、颜色含义、页面结构）每个项目不同，开工前向用户或项目文档确认。

## 1. 安全护栏：先保证不弄坏

材料是用户手里最重要的东西，而且用户常常一边让你改、一边自己也在改。每一条护栏都对应一个真实发生过的风险。

- **改前备份**：每批修改前复制整个 .key 到备份目录，命名 `_备份_HHMM_<改动说明>_<项目>.key`。说明写清“改什么之前”，回滚时一眼找到。
- **改前检查 `modified`**：脚本开头读 `modified of document`。为 true 说明用户有未保存的编辑，此时停下来问，不要保存也不要覆盖。
- **认准文件**：同名文件可能在多个目录同时打开（比如旧版和新版）。用 `file of document` 核对完整路径，不要只看 `document 1` 或名字。
- **不删除，只移走**：不要的形状移到画布外（x = -3000），不要的页设为跳过（skipped）。用户随时可以找回，备注、引用也不会断。
- **按标题找页，不按序号**：页序会变（用户自己插页）。先读标题核对，对不上就停。元素序号（`iWork item k`）同理：新增元素后序号会变，每次操作前重新 dump。
- **每完成一项就保存并汇报**：长任务拆成小项，小的先做。每项做完就 save、导出预览图、汇报“改了哪页、前→后”。中途出问题，损失最多一项。
- **改名放最后**：改文件名会让打开的文档引用失效。导出 PDF、所有修改都结束后再改名。改名用“重命名”，不要复制；旧名备份留在备份目录。

## 2. 视觉规范：先定 token，再动手

开工前把规范写成数字（或从用户之前的讨论里找出来）。所有对齐判断都对照这张表，而不是凭感觉。下面是一套 1920×1080 页面的参考值，按项目调整：

| 项 | 参考值 |
|---|---|
| 左右边距 | 47 |
| 眉题（kicker） | y 44，20pt，灰 |
| 标题 | y 89，36–40pt，最多 2 行，不擅改措辞 |
| 副标题 | y 160 |
| 内容区起点 | y ≈ 265（或紧接副标题） |
| 卡片 | 平面填充（如 #F5F5F7），间距 24，内边距 32，圆角 28/24/20（大/中/小） |
| 胶囊标签 | 圆角 = 高度一半 |
| 最小字号 | 16pt（含注释、标签、图例） |
| 字体 | 统一一种（如 PingFang SC） |

**颜色按含义用，不按好看用**：每种强调色绑定一个语义（如三条策略各一色），红色只表示问题，强调用加粗而不是加色。浅底色和对应的深色成对出现。

**明令不要的东西**：左侧装饰竖条、文本框描边、空框、元说明文字（如“本页说明：……”“颜色=……”这类给作者看的话）。

## 3. 内容表达原则

这些是用户反馈里反复出现的判断，适用于大多数规划或汇报类材料：

- **未定的事不要暗示已定**：优先级没定，就不要按时间列、按先后排卡片；把所有专题放进**一张卡片**，按类别（颜色）分组。备注里也不要说“先做 A 再做 B”。
- **整组一致的标签提到上一级**：一页里所有小点都属于同一类，就去掉每个点上的标签，只在专题标题旁放一个。点与点之间不同类时，才逐点标注。
- **临时标签统一成标准样式**：手打的〔xxx〕、【xxx】这类临时标签，改成标准胶囊样式。标签里的补充信息（如技术栈）挪进描述文字，不要丢。
- **不编数据**：数字只用已有的、来源明确的。官方口径和第三方口径不一致时，用官方的，并在备注里写明来源和日期。
- **备注和页面一致**：改页面内容时，同步检查演讲备注，别让备注说的和页面不一样。

### 每一部分怎么写

写新材料、补页，或判断某页“写得对不对”时，读 `references/section-writing.md`。它包括：
- 整体叙事线：背景 → 用户 → 竞品 → 策略 → 落地 → 规划 → 时间线与度量 → 目标与测量。
- 标题体系：眉题“章节 · 子题”，标题写结论而不是话题，副标题一句话展开。
- 每一部分的版式和写法：概览编号表、用户分层对照表、竞品“趋势总览 + 每趋势一页”、策略的“洞察 → 方案”四列、落地演示的“体验设计 | 方案演示”两栏、规划专题卡、象限全景、时间线、目标指标表、业务全景网格。
- 句子层面的写法。

## 4. 全篇对齐巡检方法

“整体看一下、对齐、歪了的修一下”这类需求，按下面的流程做，比逐页肉眼看可靠得多：

1. **导出“前”图**：全部可见页导出 PNG 到 `…/对齐前/`，再拼成每张 4 或 16 页的总览图（`scripts/contact_sheet.py`）。
2. **几何普查**：`scripts/audit.applescript` 把所有可见页的元素（类、坐标、宽高、字号、文字）导成 TSV。
3. **自动找问题**：`scripts/analyze_alignment.py` 找出几类问题：
   - 左边缘应在 47 却差 1–13px；
   - 相邻元素的 x/y/右边缘差 1–4px（几乎对齐，其实没对齐）；
   - 字号小于 16；
   - 超出右边距。
   
   `scripts/kicker_title_positions.py` 单独列出每页眉题、标题、副标题的位置，统一程度一目了然。
4. **分类修，不逐个修**：同一类问题用一段脚本统一处理（如“所有标题 → x47/y89”“演示页左栏整体左移 4px”）。卡片内的文字有意缩进，不要当成没对齐。
5. **字号放大后必查截断**：小字号改成 16pt 后，固定宽度的标签会折行或被截掉（“环节标题”变成“环节标”）。右对齐的标签往左加宽，左对齐的往右加宽。
6. **图片放大要量**：只有图片周围确实有空白、且放大后不压到别的元素时才放大。高度已经顶满的，横向放大会超界，就不要动。
7. **导出“后”图和总览图**，逐页对比，并按页写清改了什么。

## 5. Keynote AppleScript：已知的坑

细节和解决办法见 `references/applescript-gotchas.md`。最关键的几条：

- 应用名可能不是 “Keynote”（如 “Keynote Creator Studio”）。`tell application "Keynote"` 一般仍可用，报错时用 `pgrep -fl Keynote` 查实际名称。
- **不能复制形状**（“Shapes can not be copied”），**不能设置填充色、圆角、描边**。需要新样式的形状时，用第 6 节的方法。
- 可以：移动、改尺寸、改文字和文字样式（字体、字号、颜色，可细到单个字符）、新建图片和文本框、设置跳过、读写备注、导出。
- 遍历大量元素很慢（40 页可能要十几分钟），长脚本放到后台跑。
- 只导出某一页时，需要临时把其他页设为跳过。这一步一旦中途失败，整篇会被跳过。务必用 `scripts/export_slides.sh one …`，它无论成败都会恢复原状态。
- Keynote 崩溃或重启后，脚本可能完全拿不到文档（“不能获得 every document”）。这时让用户 ⌘Q 彻底退出再打开。有未保存编辑时不要替用户退出。

## 6. 原生形状重建页面

用户给了一张设计图，要求用 Keynote 原生形状做出来，以便后续编辑：

1. 用 `scripts/native_shapes_template.py`（python-pptx）按 1920×1080 **pt** 写出 PPTX。坐标和字号直接对应 Keynote 的数值。第一个元素放一个满屏背景矩形，因为粘贴只带对象，不带页面背景。
2. 用 Keynote 打开 PPTX，导出 PNG，和参考图对比。重点检查胶囊有没有溢出卡片、文字有没有折行。
3. 拷贝进目标文档。AppleScript 不能跨文档复制页或形状，要用 System Events 操作菜单：
   - 先对 PPTX 窗口执行 `perform action "AXRaise"`，再依次点菜单“编辑 → 全选”“编辑 → 拷贝”。
   - 用 `clipboard info` 确认剪贴板里是图形，而不是一段文字。
   - 把目标文档窗口 AXRaise，`set current slide` 到目标页，点“编辑 → 粘贴”。
4. 核对粘贴进来的元素数量和坐标是否与源文件一致。参考图移到画布外保留，保存。
5. 关闭临时 PPTX 前先保存主文档：关闭导入的文档可能导致 Keynote 崩溃。

## 7. 交稿前检查（按领导审视）

交稿或评审前，读 `references/final-review-checklist.md`，逐项自查。每项都按“现状 / 差距 / 改法”写，按重要性排序：

- **A 五条硬标准**：Why > What > How、目标互锁、统一 TOP3、病 - 药 - 效、遗留问题闭环。
- **B 篇幅与结构**：已落地部分不超过全篇三分之一；演示页收成代表页；竞品部分精简；节奏倒排，标出外部依赖和风险。
- **C 追问都有答案**：每个可能的追问都在页面或备注里有“问 / 答 / 依据”。
- **D 细节**：截图隐私、颜色与含义、数字出处、隐藏页旧说法、PDF 与 .key 同步、文件名日期。

自查结果给用户看。哪些要改由用户定，不要自行大改。

## 8. 汇报节奏

- 每项完成后汇报：哪一页（按标题）、改前 → 改后的文字、预览图路径、备份文件名。
- 卡住时说清是什么卡住了、需要用户做什么（具体到按哪个键、选什么），以及目前的进度。
- 改动的文件不是自己保存的（时间对不上），要指出来，不要默认是自己的。
