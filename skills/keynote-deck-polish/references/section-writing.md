# 汇报材料：每一部分怎么写

适用于“体验规划 / 设计规划 / 年度汇报”类材料。这里只讲结构和写法，具体业务内容替换成你的项目。

## 目录
1. 整体叙事线
2. 标题体系（每页都用）
3. 各部分写法：封面 · 概览 · 背景 · 用户 · 竞品 · 策略 · 落地演示 · 规划专题 · 规划全景 · 时间线与度量 · 目标与测量 · 附录全景图
4. 句子层面的写法

---

## 1. 整体叙事线

按“为什么 → 谁 → 别人 → 我们 → 做了 → 要做 → 怎么推进 → 怎么衡量”展开，每一部分回答一个问题：

| 部分 | 回答的问题 | 典型页数 |
|---|---|---|
| 背景 | 为什么现在必须变？ | 2–3 |
| 用户 | 谁在用？卡在哪？ | 3 |
| 竞品 | 行业怎么解决？趋势是什么？ | 1 + 每个趋势 1 页 |
| 策略 | 我们用哪几条策略回应？ | 1–3 |
| 落地 | 已经做出了什么？ | 若干演示页 |
| 规划 | 接下来做什么？ | 每个方向 1 页 + 全景 1 页 |
| 时间线与度量 | 怎么推进、何时验证？ | 1 |
| 目标与测量 | 用什么指标证明价值？ | 1 |

**一条主线贯穿全篇**：概览页用一句话说出主线（如“从 A 到 B：以 N 条策略推动 X 从可用到好用”）。后面每部分都回扣这条主线，策略名称和策略颜色在后面所有页面重复使用。

## 2. 标题体系（每页都用）

- **眉题**：`章节 · 子题`，灰色小字，例如“竞品洞察 · 趋势 02 · 从 A 到 B”。用来告诉观众现在在哪一部分。
- **标题 = 结论，而不是话题**。常用两种句式：
  - `关键词：结论句`，关键词用强调色。例如“运行验证：做深 X，形成 Y 闭环”。
  - 直接写一句主张。例如“生成代码后，预览、构建与设备验证帮助开发者检查应用结果”。
  - 不要写“竞品分析”“用户调研结果”这类话题式标题。
- **副标题**：一句话展开标题，常用句式：
  - “降低 A、B 与 C 成本，让开发者……”
  - “解决 A、B 的问题，让……”
  - 竞品页用“趋势：……”开头。
- 标题最多 2 行，同一部分的标题句式保持一致。

## 3. 各部分写法

### 封面
产品名 / 团队 + 主标题（版本进展 + 规划）+ 署名 / 部门 / 日期。日期随交付日更新。

### 概览
- 标题：全篇主线一句话。
- 主体：编号行列表，一行一部分：`序号 | 部分名 | 一句结论`。每行的结论要能单独成立，读完概览就知道全篇讲了什么。

### 背景（为什么变）
三层，从宏观到具体：
1. **生态 / 规模**：2–3 条关键数据，每条带口径、来源和日期。数字只用官方口径，第三方数字不混用。
2. **技术冲击**：用“从 A 走向 B”概括变化。配 3 张指标卡（指标名 + 前 → 后 + 来源）和一条里程碑时间轴（时间 + 事件 + 一句意义）。
3. **角色变化**：三阶段演进图（范式 → 主体 → 人与 AI 的分工），标题写成“A 负责……，B 负责……”。

### 用户（谁、卡在哪）
1. **分层对照表**：列是用户类型；行固定为“分层定义 / 代表客户 / 现状 / 卡点与诉求 / 问题根因 / 体验对策”。分层依据要说清（如按工程体系成熟度，而不是按行业）。
2. **洞察页**：`【洞察 N】结论句` + 一句解释 + 2–3 张用户原话卡（引用 + 来源角色，如“某某公司，负责人”）。洞察数 2–3 个。
3. **旅程页**：环形或线性阶段图。每个阶段挂痛点标签（带来源和日期），右侧写“关键变化 1/2/3”，每条是“标题 / 一句说明 / 证据”。

### 竞品（行业怎么做）
1. **趋势总览**：N 张卡，每张是“趋势编号 + 从 A 到 B + 两行说明 + 代表产品及版本 + 能力标签”。
2. **每个趋势一页**：
   - 眉题：`趋势 NN · 从 A 到 B`。
   - 标题：这个趋势带来的体验要求。
   - 副标题：“趋势：……”。
   - 主体：2 栏证据卡，每张是“截图 + 小标题 + 一句说明 + 来源（产品 版本：功能）”。
   - 底部可加一行“对我们：……”作启示。
3. **趋势之间不重复**：一个例证只放在最能说明它的那一页。

### 策略（我们怎么做）
- **洞察 → 方案流**：四列，问题与洞察（用户问题 / 竞品洞察）→ 洞察聚类 → 体验策略 → 具体设计与规划（已有设计 / 后续规划）。每行是一条策略。
- **策略命名**：短、口语、站在用户角度、有画面感（用“X 得放心 / 验得了 / 接得进”这类用户口吻的四五字短语）。每条一个固定颜色，配一句定义（“明确 X，让 Y 可见、可控”）。
- 可再加一页“阶段 × 策略”（如“26X 已做 / 27X 深化”），一页“年度重点”。

### 落地演示（已经做了什么）
- 按**任务生命周期**组织：执行前 / 执行中 / 执行后，每页讲一个可感知的改变。
- 标题：`阶段：用户可感知的变化`，例如“执行前：打开主界面即见引导，第一眼知道能做什么”。
- 版式固定为两栏：
  - 左栏“体验设计”：编号步骤时间线，当前步骤高亮，其他步骤弱化；要点是“粗体设计点 + 2–3 条细节”。
  - 右栏“方案演示”：视频或截图 + 标注（标注条对准界面区域，图例区分“必要 / 可选”）。
- 换一种产品形态时（如 GUI → CLI）：先放一页“同样流程、不同形态”，再放一页这种形态独有的设计。

### 规划专题（接下来做什么）
- 一个方向一页，眉题“规划 · 方向名”，标题“方向：主张”，副标题“降低……成本，让……”。
- 每页 2 个专题卡，每卡依次是：
  - 示意图；
  - `专题｜名称`，后面跟一个策略标签；整卡同属一个策略时，标签只放在专题标题上；
  - 一句“做什么”（深色）和一句“价值”（浅色）；
  - 规划点列表，每行一点，平台特征标签靠右。

### 规划全景
- 2×2 象限，两根轴都是有含义的维度（如“通用能力 ↔ 平台特征”“个人任务 ↔ 团队协作”）。
- 点的颜色表示策略，实心和空心区分“已有 / 新增”，图例只说明颜色和形状。
- 标题用三个短句串起三条策略。

### 时间线与度量
- 横向月份轴，标出版本节点；先放已落地的块，再放规划。
- **规划专题的优先级未定时，全部放进一张卡**，按策略颜色分组，不按时间列排。
- 下方是“度量节点”：建立基线 → 样板验证 → 版本复测，每个节点写时间段和做什么。
- 页脚两行：设计目标（定性 + “量化目标在基线测试后确认”）、业务目标（已确认的数字）。

### 目标与测量
- 顶部放 1–2 张北极星指标卡：大数字 + 口径（如“满意度 a% → b%”“支撑 N 家接入”）。
- 下方表格：`策略 | 专题 | 设计点 | 体验指标`。每条策略有一个整体感受指标（如单项 NSS），再加 2–4 个过程指标，写法是“指标名 ↑/↓：口径定义（从何时到何时、算什么占比）”。
- 没有数据的不编，写“基线测试后确认”。

### 附录：业务全景图
- 网格：行是层级（领域 / 产业 / 场景 / 产品 / 底座），列是业务线。
- 层级越高颜色越深。场景用胶囊标签，产品卡写“名称 + 一句定位 + 角色与负责人”，探索中的项目用虚线框。

## 4. 句子层面的写法

- **结论先行**：标题、卡片第一句都写判断，解释放在后面。
- **“从 A 到 B”**：描述趋势和变化的首选句式，同一部分保持这一句式。
- **用户可感知的语言**：写用户看到、做到什么（“第一眼知道能做什么”“随时介入”），少写技术名词堆砌。
- **动词 + 对象 + 结果**：“隔离并行修改，保留恢复路径”。
- **同层级句式一致**：同一列表里每条长度和语法结构相近。
- **数字带口径**：每个数字都写清指标、口径、来源和日期。官方口径优先，没有的不编。
- **标签简短**：胶囊标签 2–6 个字。
- **备注是讲稿**：讲稿按页面从左到右、从上到下讲，不说页面上没有的结论，也不说还没定的事（如优先级）。
